MCQ Tool - Expanded Idea Document
==========================================


1. PROBLEM SET (Content Structure)
===================================

A Problem Set is a JSON file containing MCQ problems for practice.

1.1 Elements of a Problem
---------------------------
- Topic: The broad subject area (e.g. "Data Visualization").
- Concept Mapping: A list of specific concepts covered within the topic
  (e.g. "Histograms", "KDE", "Box Plots"). Each problem is tagged to one
  concept from this list, enabling concept-wise analysis.
- Question Statement: The problem text presented to the learner.
- Options: A set of choices (A, B, C, D). Single-select only for v1.
- Answer Key: The correct option letter.
- Reasoning: Explanation of why the correct answer is right AND why each
  wrong option is wrong. Shown during Review (§4.1) and Reinforcement (§4.2).

1.2 Problem Set Metadata
--------------------------
- ID: Unique identifier (e.g. "DV001") used to link attempts back to the set.
- Title: Human-readable name for display during selection.
- Source: Who/what authored the set (e.g. "ChatGPT", "Professor X").
- Source_Content: Brief description of how the set was created.
- Creation_Date: When the set was authored.
- Concepts_Covered: Master list of concepts — each problem references one.

1.3 File Formats
-----------------
Single Set File:
  A JSON object with one Problem Set at the root.
  (See Sample_Problem_Set.json)

Multi-Set File:
  A JSON array containing multiple Problem Set objects.
  (See Sample_Problem_Sets.json)
  Learner selects a specific Problem Set from the file for practice.
  Selection screen displays Title, Concepts, and Problem count.

  The tool should detect and handle both formats seamlessly.


2. PRACTICE MODES
===================================

2.1 Straight
--------------
Problems presented in authored order, single pass.
Learner sees problems exactly as the author sequenced them.

2.2 Jumbled
--------------
Problems presented in randomized order, single pass.
The full set is shuffled first. If chunking is active, chunks are carved
from the shuffled order.

2.3 Corrective (New)
----------------------
A targeted re-practice mode driven by a previous attempt's results.

Setup:
- Learner uploads BOTH the Problem Set JSON AND a previous Attempt JSON.
- The tool reads the Attempt's Analysis_Report and identifies all problems
  that were NOT "Correct + Sure" — i.e. any problem where the learner
  either got it wrong or lacked full confidence.

Which problems are included:
  Category                   Included?   Why
  -------------------------  ---------   ----------------------------------------
  Correct + Sure             No          Solid grip — no need to re-practice.
  Correct + Semi-Sure        Yes         Nearly there but not fully confident.
  Correct + Doubtful         Yes         Got lucky or partial reasoning.
  Correct + Guess            Yes         Right answer but zero understanding.
  Incorrect + Sure           Yes         Blind spot — must fix.
  Incorrect + Semi-Sure      Yes         Near-miss — must clarify.
  Incorrect + Doubtful       Yes         Expected gap — must learn.
  Incorrect + Guess          Yes         Expected gap — must learn.

Flow:
- Filtered problems are presented one at a time.
- Learner selects an option.
- If correct → problem is cleared.
- If incorrect → correct option and reasoning are shown immediately,
  problem stays in the queue for another attempt.
- Session keeps running until all problems are answered correctly.
- Learner can exit early at any point.

This mode bridges the gap between a full re-attempt and the post-session
Reinforcement (§4.2). It is useful days or weeks after the original attempt
to check whether the learner has truly internalized the corrections.


3. PRACTICE SESSION (3 Phases)
===================================

The core learning loop. A session may cover the full Problem Set or a
chunk of it. Each session passes through three phases in sequence.
(Corrective mode has a simplified flow — see §2.3.)

Phase 1: Setup
---------------
- Learner uploads a Problem Set JSON file (single or multi-set).
- If multi-set: learner selects a specific Problem Set.
- Learner selects a Practice Mode:
    • Straight / Jumbled → standard practice
    • Corrective → also requires uploading a previous Attempt JSON
- Learner selects a Chunk Size (Straight / Jumbled only):
    • All (entire set in one go)
    • 5 questions per chunk
    • 10 questions per chunk
  Chunking lets the learner practice in manageable batches. After each
  chunk completes Phase 3, learner can continue to the next chunk or stop.

Phase 2: Attempt (Per Question)
--------------------------------
For each problem in the chunk (in mode order):
- Problem Statement and Options are displayed.
- Learner selects one Option via radio button.
- Learner selects a Confidence Level:
    S  = Sure         — "I'm confident this is correct"
    SS = Semi-Sure    — "I think so, but not fully certain"
    D  = Doubtful     — "Probably wrong, but trying"
    G  = Guess        — "No idea, picking at random"
- Learner navigates to the next problem or submits the chunk.
- Time spent on each problem is tracked automatically (in seconds).
  The timer starts when the problem is displayed and stops when the
  learner moves to the next problem or submits.
- Total session time is the sum of all per-problem times.

  The confidence tag is the key differentiator of this tool.
  It transforms a simple quiz into a metacognitive exercise — the learner
  is not just answering, but assessing how well they know the answer.

Phase 3: Post-Attempt (after chunk is submitted)
--------------------------------------------------
Three sequential steps run after every chunk submission:

  Step 1 → Analysis Statistics (§5)
           Learner sees performance numbers — accuracy overall
           and broken down by confidence level.

  Step 2 → Review Session (§4.1)
           Problems shown in priority order with correct answers
           and reasoning. Learner reads and absorbs.

  Step 3 → Reinforcement Session (§4.2)
           Same problems re-asked until learner answers them all
           correctly. Active recall after passive review.

After Step 3, if more chunks remain:
  → Learner chooses "Continue to next chunk" or "Stop here".


4. FEEDBACK & REINFORCEMENT (Post-Practice)
=============================================

Two distinct sessions run back-to-back after each practice chunk.
Review is passive learning. Reinforcement is active recall.

4.1 Review Session (Passive — Read & Absorb)
----------------------------------------------
Problems are shown in a specific priority order designed to maximize
learning impact. Each problem displays:
  - Problem Statement
  - All Options (learner's selection highlighted)
  - Correct Option (highlighted differently)
  - Full Reasoning/Explanation
  - The learner's Confidence Tag (for self-reflection)

Priority order — problems needing the most attention come first:

Priority   Category                  Why This Order
--------   ----------------------    ----------------------------------------
1          Correct + Semi-Sure       Nearly there — reinforce the reasoning
                                     so the learner moves from SS → S.
2          Correct + Doubtful        Lucky or partial reasoning — needs full
                                     explanation to build real understanding.
3          Incorrect + Sure          BLIND SPOT — learner was confident but
                                     wrong. Most dangerous gap. Must fix.
4          Incorrect + Doubtful      Expected gap — learner suspected they
                                     were wrong. Teach the concept clearly.
5          Correct + Guess           No real understanding — right answer by
                                     chance. Treat as fresh learning moment.
6          Incorrect + Guess         Expected gap — no knowledge, no surprise.
                                     Teach from scratch.

Skipped: Correct + Sure — solid cognitive grip. No review needed.

4.2 Reinforcement Session (Active — Re-Attempt Until Correct)
--------------------------------------------------------------
After the Review Session, learner has seen all correct answers and
reasoning. Now the same problems are presented again for re-attempt
to cement learning through active recall.

Rules:
- All problems from §4.1 are queued (everything except Correct + Sure).
- Problems presented one at a time.
- If learner answers correctly → problem is cleared from the queue.
- If learner answers incorrectly → correct option and reasoning shown
  immediately, problem stays in the queue for another attempt.
- Session continues looping until queue is empty (all answered correctly).
- Learner has the option to exit early at any point.

Critical Rule:
  *** Responses in the Reinforcement Session do NOT affect
      the Analysis Statistics from Step 1. ***
  Statistics reflect only the original attempt (Phase 2).
  Reinforcement is purely a learning exercise, not a scoring one.

4.3 Relationship Between Reinforcement (§4.2) and Corrective Mode (§2.3)
--------------------------------------------------------------------------
Both involve re-attempting problems until correct. The difference:

  Aspect             Reinforcement (§4.2)       Corrective Mode (§2.3)
  ─────────────────  ─────────────────────────  ──────────────────────────
  When               Immediately after review   Days/weeks later
  Input              Current session results     A saved Attempt JSON file
  Purpose            Cement just-reviewed info   Verify long-term retention
  Affects stats?     No                         No (learning exercise only)
  Part of session?   Yes (Phase 3, Step 3)      Standalone session


5. ANALYSIS STATISTICS (Per Session)
======================================

Computed and displayed immediately after each chunk is submitted
(Phase 3, Step 1). These are the core metrics for understanding
cognitive grip.

5.1 Core Metrics
-----------------
#   Metric                                    What It Answers
--  ----------------------------------------  -----------------------------------
1   Attempted Questions                       How many problems the learner answered
2   Total Accuracy (%)                        Overall correctness rate
3   Accuracy across Sure (%)                  "When I say Sure, am I actually right?"
4   Accuracy across Semi-Sure (%)             "When I say Semi-Sure, am I right?"
5   Accuracy across Doubtful (%)              "When I doubt myself, how often am
                                               I still right?"
6   Sure % in Correct Questions               "Of what I got right, how much did
                                               I truly know (Sure)?"
7   Semi-Sure % in Correct Questions          "Of what I got right, how much was
                                               I almost-sure about?"

5.2 What These Metrics Reveal
-------------------------------
Metrics 3–5 measure CALIBRATION:
  How well the learner's confidence matches actual accuracy.
  - High Accuracy in Sure = good self-calibration.
  - Low Accuracy in Sure = dangerous blind spots.
  - High Accuracy in Doubtful = underconfidence (knows more than they think).

Metrics 6–7 measure KNOWLEDGE QUALITY:
  Of everything the learner got right, how much was genuine knowledge
  vs. lucky guessing?
  - High (Sure% + Semi-Sure%) in Correct = genuine, reliable knowledge.
  - High (Doubtful% + Guess%) in Correct = fragile, luck-based correctness.

Key Insight Metric:
  Accuracy in Sure and Semi-Sure combined shows how good the learner's
  self-assessment is about their own knowledge. This is the single most
  important number for tracking cognitive grip.

5.3 Accuracy–Confidence Matrix (Visual Summary)
-------------------------------------------------
All results map to a 4×2 matrix:

                      Correct              Incorrect
                ┌───────────────────┬───────────────────┐
    Sure (S)    │  Solid Grip       │  Blind Spot !!    │
                │  (no review)      │  (highest alert)  │
                ├───────────────────┼───────────────────┤
  Semi-Sure(SS) │  Nearly There     │  Near-Miss        │
                │  (reinforce)      │  (clarify)        │
                ├───────────────────┼───────────────────┤
  Doubtful (D)  │  Underconfident   │  Expected Gap     │
                │  (build certainty)│  (teach)          │
                ├───────────────────┼───────────────────┤
    Guess (G)   │  Lucky            │  Expected Gap     │
                │  (learn properly) │  (teach)          │
                └───────────────────┴───────────────────┘

Each cell shows a count and percentage. Gives a single-glance view
of where the learner stands across all confidence–accuracy combinations.

5.4 Concept-Wise Breakdown
----------------------------
Since each problem has a Concept_Map, statistics can be grouped by concept:

  Concept                         Problems   Correct   Accuracy
  ──────────────────────────────  ────────   ───────   ────────
  Histograms                      1          1         100%
  Kernel Density Estimate (KDE)   1          0         0%

Tells the learner exactly which concepts need work, rather than
just an overall accuracy number.


6. EXPORT & LONGITUDINAL ANALYSIS
===================================

6.1 Export
-----------
- After each session, learner can download the Attempt Record as a JSON file.
  (Format as in Sample_Problem_Set_Attempted.json)
- Contains:
    • Session metadata (Problem_Set_ID, Attempt_Date, unique session ID)
    • Per-problem responses (selected option + confidence level)
    • Full Analysis_Report (all statistics from §5 + feedback review order)
- File naming: {SetID}_{Date}_{Time}_Attempted.json
  (e.g. DV001_20240612_143022_Attempted.json)

6.2 Cross-Attempt Analysis (Longitudinal View)
------------------------------------------------
Learner uploads multiple Attempt JSON files for the same Problem Set.
The tool shows performance trends over time:

  What To Track                       What It Shows
  ----------------------------------  ------------------------------------
  Total Accuracy trend                "Am I learning the content?"
  Accuracy in Sure trend              "Am I reducing my blind spots?"
  Sure% in Correct trend              "Is more of my knowledge genuine?"
  Blind Spot count trend              "Are my dangerous gaps shrinking?"
  Concept-wise accuracy over time     "Which concepts are improving?"
  Confidence distribution shift       "Am I moving from Guess → Sure?"

This fulfills the core vision: analyzing how cognitive grip improves over time.

6.3 Corrective Mode as Longitudinal Tool
------------------------------------------
The Corrective mode (§2.3) plugs directly into the longitudinal workflow:
  1. Learner practices a set → exports Attempt JSON.
  2. Days later, learner uploads the set + old Attempt JSON in Corrective mode.
  3. Only weak/incorrect problems are re-practiced.
  4. New Attempt JSON is exported.
  5. Comparing old and new Attempts shows exactly which gaps were closed.

This creates a natural cycle: Practice → Export → Review gaps → Correct → Export → Compare.
